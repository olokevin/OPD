# NP Trainer V2 — Packed, CUDA-Graphed Decode Driver

> **One line.** V2 is a *decode-driver-only* rewrite of the NP trainer that (M1) packs all prompts'
> `(1+N)` rows into ONE eager wide forward per token with per-prompt shared-prefix KV + active-mask
> ragged handling, then (M2) CUDA-graphs that forward by moving noise application into a static
> in-graph `y += σ·u_buf` op whose buffer the host refills from the existing tested `draw_noise`.
> No NP math changes. Verified at each milestone by serial-vs-packed numerical parity plus the
> preserved σ=0 / cos≈0.41 / unit-test gates, and measured for speedup.

**Status:** design approved 2026-06-03. Companion to `docs/wiki/zo_np_trainer.md` §8.
**Branch context:** `np-fold-xcapture` (V1.1, commit `21534aa`, x_t-capture folded; estimator `(L_q−mean)/σ`).
**Approach (decided):** Approach A — add the packed path as **new** worker methods beside V1, which stays
callable as the parity oracle. V1 is the golden reference for the entire V2 effort.

---

## 1. Motivation (the bottleneck)

Profiled 2026-06-03 (`docs/wiki/zo_np_trainer.md` §8.3, memory `zo-np-threadcap-384core`):

```
meta (attn_metadata build) = 0.31 ms/tok   (~1%)
fwd  (the 1+N=65-row forward) = 13–20 ms/tok (~99%)
```

V1 runs that eager `(1+N)`-row forward ~1024×/sequence × `batch_size` sequences **serially** (one Ray RPC
per sequence). Full default config (BATCH 64 × 1024 tok + 200-prompt eval) ≈ **72 min/step**; smoke
(BATCH 4, RESP 128, eval off) ≈ **28–36 s/step**.

The forward is 99% of the cost, so V2 attacks the forward on two axes (§8.4):

1. **Batch across prompts** — pack all active prompts' `(1+N)` rows into ONE wide forward per token
   instead of `batch_size` sequential tiny ones. Far better GPU utilization at the same total FLOPs.
2. **CUDA-graph the step forward** — remove per-token eager dispatch overhead. Blocker: the eager
   Python perturbation hook. Fix: express perturbation as a graph-capturable op (host-refilled buffer).

**Decision (scope):** both axes, **packing first** (bigger, lower-risk win lands and is measurable
before the harder graph work).

---

## 2. Invariants V2 MUST preserve (not a math change)

V2 is a **performance rewrite of the decode driver only**. The following are preserved *by construction*
and re-checked at each milestone:

- **σ=0 byte-equivalence** vs stock greedy `LLM.generate` (`np_checks/check_decode_sigma0.py`).
- **cos(NP δW, autograd) ≈ +0.41 at N=64** (`np_checks/check_grad_cosine.py`; offline, decode-driver-independent).
- **Per-token `(L_q, L_clean, u, x)` semantics + the `(L_q−mean)/σ` estimator unchanged.**
- **Update rule / sign** (`W ← W − lr·δW`, gradient descent) unchanged.
- **Zero ES files touched** (`git diff --stat main..HEAD -- verl/verl/trainer/es/ ...` stays empty).

**Untouched modules:** `grad_estimator.py`, `teacher_scorer.py`, `seeding.py`, `layer_resolve.py`,
`assemble_layer_delta`, `apply_node_update`, NCCL broadcast. V2 changes *how rows are assembled and run*,
not the NP math, the teacher scoring, or the weight update.

## 3. Architecture & milestones

| Component | Where | Responsibility |
|---|---|---|
| Packed decode driver | `np_worker_extension.py` → `run_np_decode_packed`, `_np_step_forward_packed`, `_np_build_attn_metadata_packed`, `_np_prefill_packed` | Build & run the `B_pack×(1+N)`-row forward; per-prompt KV/slots, active mask, per-token signal capture. |
| Graph-capturable perturbation | `PerturbedLinear` (new `perturb_graph` mode) + persistent `u_buf` | In-graph static `y[perturbed] += σ·u_buf`; host refills `u_buf` from `draw_noise` before each replay. |
| Graph harness | `np_worker_extension.py` → `_np_capture_graph`, `_np_replay_step` | Capture the packed step forward once at fixed `B_pack×(1+N)` width; per token refill static input buffers in place and `replay()`. |
| Trainer wiring | `ray_trainer.py` `fit()` | `np.decode_mode ∈ {serial, packed}`; chunk `batch_size` prompts into `ceil(batch_size/B_pack)` waves; accumulate ALL waves' per-token signals into ONE δW per step (math identical to V1). |
| Config | `np_trainer.yaml` | New keys `decode_mode`, `pack_width`, `use_cuda_graph`. |

**Milestones** (each independently verifiable & revertable; `serial`/V1 stays callable throughout):

1. **M1 — Packed eager forward.** One eager forward of `B_pack×(1+N)` rows replaces `B_pack` serial
   forwards. `use_cuda_graph=false`. **Gate:** per-token `(L_q, L_clean, u, x)` + clean tokens match V1
   within bf16 tolerance on the same prompts/seeds; σ=0 packed byte-equiv passes; report s/step vs V1.
2. **M2 — CUDA-graphed packed forward.** Swap eager hook → pre-filled-buffer op; capture/replay the
   packed step. `use_cuda_graph=true`. **Gate:** graph output == eager packed output (parity);
   cos≈0.41 still holds; report s/step vs M1 and V1.
3. **M3 — Cleanup/retire (optional).** Once M2 proven, optionally make `packed` the default; keep
   `serial` reachable as the parity oracle. No math change.

## 4. Packed row layout & KV bookkeeping (core of M1)

### 4.1 Row layout (one wave of `B_pack` prompts)

Flat batch of `R = B_pack × (1+N)` rows, grouped per prompt and contiguous:

```
prompt 0:  [ clean₀ | pert₀,₁ … pert₀,N ]   ← rows 0 … N
prompt 1:  [ clean₁ | pert₁,₁ … pert₁,N ]   ← rows (1+N) … 2(1+N)-1
   ⋮
prompt B-1:[ clean_{B-1} | pert_{B-1},₁ … ]
```

Prompt `p` owns the fixed row block `[p·(1+N) : (p+1)·(1+N)]`; row `p·(1+N)` is its clean row, the next
`N` are its perturbations. Fixed blocking lets the graph index `u_buf` and the perturbed-row slice
statically.

### 4.2 Per-prompt KV (key correctness point)

Each prompt keeps its **own** shared-prefix KV (V1 already does this per prompt; packing means `B_pack`
disjoint KV regions live at once). Per prompt `p`:

- its own `block_ids` — a disjoint high-indexed scratch slice of the GPU block pool, one slice per
  prompt-row-block, sized to `max_model_len`;
- its **clean row** writes KV at its own `kv_cursor_p`
  (slot = `block_ids_p[cursor//bs]·bs + cursor%bs`);
- its **N perturbed rows** all write `slot=-1` (PAD) → `reshape_and_cache` skips them, so perturbations
  leave no KV trail (V1 invariant, preserved per prompt);
- a prompt's perturbed rows **attend only its own prefix** — enforced by per-row `seq_lens` and the
  per-prompt block-table rows in the packed `attn_metadata`.

**Scratch-KV sizing + fail-fast guard.** Total scratch ≈ `B_pack × ceil(max_model_len/block_size)`
blocks (e.g. `B_pack=8`, `max_model_len≈1024+prompt`, `block_size=16` → ~8×72 ≈ 576 blocks). Before the
first packed wave (and before graph capture), assert
`B_pack × blocks_per_prompt ≤ num_gpu_blocks` with a message naming both numbers and suggesting a lower
`pack_width`. Fail fast rather than corrupt KV.

### 4.3 Packed `attn_metadata` (`_np_build_attn_metadata_packed`)

Generalizes V1's builder from `num_reqs = 1+N` (one prompt) to `num_reqs = B_pack×(1+N)`:

- `query_lens = [1]×R` (one query token per row, as V1);
- `seq_lens[row]` = that prompt's `kv_cursor_p + 1` (**per-prompt**, not shared);
- `block_table_tensor` = per-row block_ids → rows in the same prompt block share identical block_ids;
  different prompts differ;
- `slot_mapping` = `[clean_slot_p, -1×N]` concatenated over prompts;
- `positions[row]` = that prompt's `q_pos_p`.

This is the one genuinely new piece of vLLM-internal code; a row-replicated extension of the V1 builder
that already passes the σ=0 gate, so the gate transfers.

### 4.4 Ragged handling — fixed width + active mask (decided)

When prompt `p` hits EOS at step `t`, set `active_mask[p]=0`. Its rows stay in the batch as harmless
padding: feed a valid `input_ids`/`positions` (**re-feed its last token at its own clean slot** — re-writing
identical KV is a no-op, decided over a throwaway `-1` slot) but **drop its row from sampling and from the
captured signal lists**. The wave runs until **all prompts in it are inactive or `t == max_tokens`**.
Finished prompts' tail tokens cost FLOPs but never pollute δW (their per-token signals are simply not
appended).

### 4.5 Signal capture per token

`_np_step_forward_packed` returns `[R, vocab]` logits. Slice each prompt's clean row (`logits[p·(1+N)]`)
for sampling. `(L_q, L_clean, u, x)` for prompt `p` are captured exactly as V1 captures them for a single
prompt — indexed into prompt `p`'s row block. `captured_x[p]` = clean row's layer input;
`captured_u[p]` = stacked `u` for `p`'s `N` rows.

### 4.6 Seed identity (packing must not change the noise)

V1 noise depends on `(global_seed, step, layer, rollout, q)`. In a wave each prompt slot needs a stable,
distinct `rollout_idx` so two prompts in the same wave don't draw identical `u`. Assign each (prompt,
rollout) slot a unique `rollout_idx` = its global index `step*batch_size + b` (the same value V1's serial
loop passes), and seed `u_buf[p,q]` with `noise_seed(..., rollout=rollout_idx_p, q)`. This makes packed
noise **identical** to what V1's serial loop drew for the same prompt — a precondition for the M1 parity
gate. `n_rollout>1` ⇒ `batch_size×n_rollout` slots chunked into waves; each (prompt, rollout) is one slot.

## 5. Graph-capturable perturbation op (M2)

Implemented as a **captured Torch op reading a persistent buffer**, not new CUDA C++.

### 5.1 The blocker

V1's `PerturbedLinear.forward` does two graph-hostile things per call: (a) regenerates `u` via
`torch.Generator().manual_seed(...)` (data-dependent control flow + fresh allocation), and (b) loops
`for q in range(n_sample): y[n_clean+q] += σ·u`. Neither is capturable.

### 5.2 The fix — split regeneration (host, outside graph) from application (static, inside graph)

- **Persistent buffer.** On capture, allocate `u_buf` once: shape `[B_pack, N, d_out]` (or flat
  `[B_pack·N, d_out]` aligned to perturbed-row indices), dtype = layer output dtype, on device. Lives as
  long as the captured graph.
- **Inside the graph (static, captured)** — `PerturbedLinear` runs a new `perturb_graph` mode whose
  forward is only:
  ```
  y[perturbed_row_idx] += sigma * u_buf          # elementwise, fixed shapes, graph-safe
  st["captured_x"][name] = x[clean_row_idx]      # view into static buffer, no alloc
  ```
  `perturbed_row_idx` / `clean_row_idx` are the fixed per-prompt row offsets (§4.1) — constant for the
  graph's life, so baked in. `sigma` is a captured scalar. No RNG, no Python loop, no allocation.
- **Outside the graph (host, per token, before `replay()`)** — refill `u_buf` in place from the existing
  **tested** `draw_noise`:
  ```
  for p in active prompts, q in range(N):
      u_buf[p, q].copy_( draw_noise(noise_seed(seed, t, layer, rollout_p, q), (d_out,), ...) )
  ```
  `copy_` into the persistent buffer is a graph-input update, exactly like refilling
  `input_ids`/`positions`/`slot_mapping`. Noise regeneration stays in the Python path that already passes
  the cos and byte-equiv gates → **parity by construction**.

### 5.3 Why this preserves the invariants

The *value* written is bit-identical to V1's `y[n_clean+q] += σ·u` (same `draw_noise` output, same `σ`);
only *where the loop lives* changed (host-side buffer fill vs. in-forward loop). σ=0 (set `u_buf=0` or
`σ=0` → graph adds nothing → byte-equiv) and cos≈0.41 transfer directly.

### 5.4 Buffer-fill cost (conditional escalation)

Refilling `u_buf` is `B_pack·N·d_out` noise draws/token on the host-launched `draw_noise` path. M2
**measures** the buffer-fill time as a fraction of the now-graphed forward. **Only if** it's a non-trivial
fraction do we escalate to a fused noise-gen kernel (Philox, counter-based RNG) — written into the plan as
a *conditional* follow-up task with its own RNG-parity sub-gate, **not** done up front. Pre-kernel
mitigation if needed: fill `u_buf` on a side CUDA stream overlapping the previous replay (seeds for step
`t+1` are known ahead).

### 5.5 What stays eager

`compute_logits(hidden)` and clean-row sampling stay outside the graph (sampling is data-dependent). The
graph covers the **model forward of the packed step** (the 99%) and writes `hidden` into a static output
buffer (`hidden_buf`) that the eager `compute_logits` then reads. V1's
`set_forward_context(..., cudagraph_runtime_mode=NONE)` is replaced by an explicit capture; V1's comment
"CUDA graphs would skip our slot rewrites" no longer applies because `slot_mapping` is now a refilled
static input the captured graph reads, not a per-call rewrite.

### 5.6 Capture mechanics (`_np_capture_graph`)

Standard `torch.cuda.CUDAGraph` capture: warm up a few eager packed steps (cuBLAS workspace/autotune),
then capture one packed step forward with all inputs bound to persistent buffers (`input_ids_buf`,
`positions_buf`, `slot_mapping_buf`, `seq_lens_buf`, `block_table_buf`, `u_buf`, output `hidden_buf`). Per
token: `copy_` new values into each input buffer, `graph.replay()`, read `hidden_buf`. Captured **once per
`(layer_or_shape, B_pack)`** — `en_layerwise_perturbation` round-robins one layer/step and all targeted
layers are the same module type/shape (`down_proj`), so one graph (or one per distinct `d_out`) suffices;
cache captured graphs keyed by `(layer_name_or_shape, B_pack)`.

### 5.7 Named risk + ordering

vLLM's attention backend (FLASH_ATTN, which passed the V1 σ=0 gate) must be CUDA-graph-capturable with our
**hand-built** `attn_metadata` bound to static tensors. Most vLLM attn kernels are graph-safe (that's how
vLLM's own graphs work), but our hand-built metadata path is not vLLM's normal capture path. Therefore
**M2's first task is a minimal capture-replay spike** on a single packed step (assert `graph_hidden ==
eager_hidden` bitwise/within capture tolerance) **before** building the full per-token replay loop. If the
metadata-in-graph assumption breaks, we find out in task 1, not at integration. Fallback: M1 (eager
packed) still ships the packing win alone.

## 6. Trainer wiring & config (the wave loop)

### 6.1 New config keys (`np_trainer.yaml`)

```yaml
np:
  decode_mode: serial      # serial (V1) | packed (V2)
  pack_width: 8            # B_pack: prompts per packed forward (graph captured at this width)
  use_cuda_graph: false    # false = M1 eager packed; true = M2 graphed packed
```

Defaults keep V1 behavior (`serial`) so nothing regresses until explicitly switched. `pack_width` and
`use_cuda_graph` only matter when `decode_mode=packed`.

### 6.2 The wave loop (replaces V1's serial `for b … for r …` inner body, per active layer)

```
prompts_this_step = [ prompts[(step*batch_size + b) % len(prompts)] for b in range(batch_size) ]
rollout_ids       = [ step*batch_size + b                           for b in range(batch_size) ]  # stable seed identity (§4.6)

L_q_steps, L_clean_steps, u_steps, x_steps = [], [], [], []
for wave in chunks(zip(prompts_this_step, rollout_ids), size=B_pack):     # ceil(batch_size / B_pack) waves
    out = ray.get(engine0.collective_rpc.remote(
        "run_np_decode_packed",
        args=(wave_pids, sp, layer_name, np_cfg, wave_rollout_ids, use_cuda_graph)))[0]
    for p in range(len(wave)):
        if not out["clean_tokens"][p]: continue
        full = wave_pids[p] + out["clean_tokens"][p]
        L_q, L_clean = self.scorer.score_rollout(full, out["candidate_logits"][p])   # teacher scorer UNCHANGED
        L_q_steps += L_q;  L_clean_steps += L_clean
        u_steps += [out["captured_u"][p][t] for t in range(len(out["candidate_logits"][p]))]
        x_steps += [out["captured_x"][p][t] for t in range(len(out["candidate_logits"][p]))]

# identical from here down — ONE assemble_and_apply per step:
assemble_and_apply(layer_name, L_q_steps, L_clean_steps, u_steps, x_steps, ...)
broadcast_layer_weights(...)
```

### 6.3 Key points

- **One δW per step, unchanged.** All waves' per-token signals land in the same four accumulators, fed
  once to the untouched `assemble_and_apply`. Effective mini-batch = `batch_size × n_rollout × T` exactly
  as V1 (§6 variance note in the wiki). `B_pack` is purely a GPU-tiling knob — it does **not** change the
  math, only how many forwards the wave loop issues.
- **Teacher scoring stays per-prompt and unchanged.** `TeacherScorer.score_rollout` is called once per
  prompt on its clean rollout, exactly as V1 — packing is student-side only. Teacher prefill batching is
  out of scope (student forward is 99%).
- **`n_rollout` handling.** Each (prompt, rollout) pair is one wave slot with its own `rollout_id`;
  `n_rollout>1` ⇒ `batch_size×n_rollout` slots chunked into waves. Back-compat without special-casing.
- **Held-out KL probe (`_heldout_kl`).** Stays on the `serial` path (decodes ≤16 fixed prompts once per
  eval interval — not a bottleneck; keeps the progress probe on the proven path).
- **`decode_mode=serial` is the parity oracle.** Same prompts/seeds through both `serial` and `packed`,
  diff per-token `(L_q, L_clean, u, x)` + clean tokens. Same seeds + `draw_noise` ⇒ differences ≤ bf16
  reduction-order noise; the gate asserts within tolerance.
- **Memory guard.** Before capture (or before the first eager packed wave) assert
  `B_pack × blocks_per_prompt ≤ num_gpu_blocks` (§4.2).

## 7. Verification & milestone gates

Success criterion (decided): **numerical parity + measured speedup**, both hard gates.

### 7.1 Existing gates that must keep passing (regression guards)

| Gate | Script | When |
|---|---|---|
| σ=0 byte-equivalence | `np_checks/check_decode_sigma0.py` (extended for packed) | M1 + M2 |
| cos(NP δW, autograd) ≈ +0.41 @ N=64 | `np_checks/check_grad_cosine.py` | M2 (offline; confirms math untouched) |
| CPU unit suite (32 tests, incl. gradient-descent-sign) | `pytest verl/tests/np/` | M1 + M2 |
| ES regression (zero ES files touched) | `git diff --stat main..HEAD -- verl/.../es/` | both — must stay empty |

### 7.2 New parity gate (heart of V2 acceptance) — `np_checks/check_packed_parity.py`

- Same model/teacher/prompts/seeds. Run **`serial`** and **`packed`** decode on the same prompt set.
- Assert, per prompt, per token: identical clean tokens; `u` bit-identical (same seeds → same
  `draw_noise`); `x`, `L_q`, `L_clean` equal within **bf16 reduction-order tolerance** (the only
  legitimate source of difference is batched vs. serial matmul reduction order — documented, bounded,
  e.g. `rtol ≤ 1e-2` on the bf16 path; δW *direction* unaffected).
- **M1:** `packed` eager vs `serial`. **M2:** `packed` graphed vs `packed` eager (isolates the graph from
  the packing).

### 7.3 σ=0 packed extension

Generalize `check_decode_sigma0.py`: with `σ=0`, every perturbed row equals the clean row, and packed
clean tokens match stock greedy `LLM.generate` **for every prompt in the wave** — proving the packed
`attn_metadata` (per-prompt block_ids/seq_lens/slot) routes each prompt to its own prefix. Single most
important new correctness check for §4.

### 7.4 Capture spike (M2 task 1)

Before the full replay loop: capture one packed step, replay it, assert `graph_hidden == eager_hidden`
(bitwise/within capture tolerance) on a single wave. Fails fast if hand-built `attn_metadata`-in-graph is
not capturable.

### 7.5 Speedup measurement (reported, not a fixed target)

Reuse the per-phase `torch.cuda.synchronize` timing in the step forward + end-to-end s/step. Report a small
table at each milestone — **V1 serial** vs **M1 packed-eager** vs **M2 packed-graphed** — on (a) the smoke
config (BATCH 4, RESP 128, eval off; V1 baseline ~28–36 s/step) and (b) a documented memory-fitting subset
of the full config. Also report the chosen `pack_width` ceiling and peak memory. Gate: measured, reported,
and a real improvement at each axis (no fixed pass/fail number — the packed-batch memory ceiling on one
A800 with both engines resident is not known up front).

### 7.6 Smoke e2e per milestone

5-iter end-to-end on Qwen3-1.7B student / Keven16 4B teacher (the §5 e2e gate), `decode_mode=packed`:
assert update lands (`changed_frac>0`), `sync_ok=1`, no crash, held-out KL finite. Confirms the whole
pipeline (decode → score → assemble → apply → broadcast) works through the new driver.

## 8. Scope boundaries & risks

### 8.1 Explicitly OUT of scope for V2

- Teacher-side batching (teacher scoring stays per-prompt; student forward is 99%).
- Fused noise-gen CUDA kernel (Philox) — only a *conditional* follow-up if §5.4 buffer-fill is non-trivial.
- Compact-and-continue / length bucketing — rejected; fixed-width + active mask only.
- Multi-engine packed decode — V1 decodes on engine 0 then broadcasts; V2 keeps that. Packing is within
  one engine's wave.
- Any NP math change (`grad_estimator`, `teacher_scorer`, `seeding`, `assemble_layer_delta` untouched).
- Retiring V1 (`serial`) — kept as the parity oracle; making `packed` the default (M3) is optional and
  gated on M2.

### 8.2 Named risks + mitigations

| Risk | Mitigation |
|---|---|
| Hand-built `attn_metadata` not graph-capturable with FLASH_ATTN | M2 **task 1** is the capture spike; fail fast before the replay loop. Fallback: M1 (eager packed) still ships the packing win alone. |
| Per-prompt scratch KV collisions across `B_pack` prompts | Disjoint high-indexed slices; fail-fast assert on `B_pack × blocks_per_prompt ≤ num_gpu_blocks`; σ=0 packed gate proves correct prefix routing. |
| bf16 reduction-order drift (batched vs serial) inflates parity diff | Parity gate uses bounded `rtol` tolerance, documents reduction-order as the only legitimate source; cos≈0.41 gate confirms δW *direction* unaffected. |
| OOM at chosen `pack_width` with both engines resident | `pack_width` configurable; start small (4–8), document ceiling; memory guard asserts before capture. |
| `compute_logits`/sampling can't be in-graph | By design they stay eager; graph covers only the model forward (the 99%) writing a static `hidden_buf`. |
